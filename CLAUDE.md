# CLAUDE.md

Context for working on this repo. Read before making changes.

## Working style

- Plan first, get agreement, then build. Never run destructive or broad operations (force push, history rewrite, deleting branches, changing repo visibility) without an explicit go-ahead.
- Prefer vetted, community-standard solutions over new tooling. Keep it simple.
- Before revising code, critique it against specific criteria and write the findings down, then change it.
- Writing in UI and docs: direct, calm, short sentences. No em dashes. No emojis. Sentence case.
- In the UI, do not call the verdict a "call"; readers take it as a phone call. Name it (Go, Caution or Stay off) or describe what is checked. "Call" is fine in code and these docs.

## What this is

RoWhether is a single-page rowing conditions app for a curated list of locations, with Putney Landing, VT, first: the Connecticut River at the Putney Rowing Club docks. Used mostly on phones, installed to the home screen as a PWA. Vanilla JS ES modules bundled with Vite. No framework. Deployed as a Cloudflare Worker that serves the built static files. The Worker has three API routes: `/api/info` (which instance this is, and the open counter), `/api/suggest` (the suggestion form) and `/api/reports` (dock reports, D1). Everything else is static.

## Branches, production and dev

- Production is https://rowhether.com/, a custom domain on the `rowhether` Worker. `SITE_URL` in `src/config.js` holds it for shared links; the canonical and Open Graph tags in `index.html` repeat it. Use it for any production link.
- Workers Builds deploys production on every push to `master`, the repo's default branch. Pushing there changes the live app within a minute. Do not push experiments there.
- `dev` is the dev instance. With Preview builds turned on for the `rowhether` Worker, every push to a non-production branch builds a Worker Preview at `<branch>-rowhether.<subdomain>.workers.dev`, so `dev` lives at `dev-rowhether.<subdomain>.workers.dev`. Work on `dev` (or a branch off it) and check it there.
- Previews use the `previews` block in `wrangler.jsonc`, not production settings: `APP_ENV` is `dev`, separate rate limiter namespaces, and the `rowhether-dev` D1 database. No secrets are set for Previews, so the suggestion form stays hidden there and never files real issues. The app shows a "Dev" label next to the title when `/api/info` says it is not production.
- D1 schema lives in `migrations/`. Apply it to the dev database with `npx wrangler d1 migrations apply PREVIEW_DB --remote -c wrangler.preview-migrations.jsonc`.
- Production has no D1 binding yet, so dock reports stay off there even after a merge. To turn them on, create a production database, add it at the top level of `wrangler.jsonc`, and apply the migrations to it.
- To ship from dev: merge `dev` into `master`. Only with the owner's go-ahead.

## Hard constraints

- No runtime loads from third-party CDNs. SunCalc 1.9.0 and the Archivo variable font (`@fontsource-variable/archivo`) are npm dependencies bundled into the build, so the app shell works offline. Pin exact versions in `package.json` for anything added. One exception: the Cloudflare Turnstile script, which cannot be bundled. It loads only when the suggestion form is first opened.
- Weather and river data is fetched client-side from keyless APIs that send `Access-Control-Allow-Origin: *`. The browser never holds an API key. Anything that needs a key goes in the Worker (`worker/`), with the key stored as a Worker secret, never in the repo or `wrangler.jsonc`.
- The service worker precaches the app shell and the curated location files (`locations/*.json`, not the `<slug>.html` shells); it never caches API responses. Freshness of data is handled by the app's own localStorage cache. A new worker skips waiting and claims the open page (`skipWaiting` and `clientsClaim` in `vite.config.js`), and the page reloads once onto the new build, so an installed copy never waits for the browser to close. The static pages (`/privacy`) are files the host serves, not routes of the app: `navigateFallbackDenylist` names them and `privacy.html` is precached, so `/privacy` opens offline and is never answered with `index.html`.
- The open counter (`src/info.js`, `worker/index.js`, 07 14.3) is the only count of use. Once per start, when the first address is answered, the app asks `GET /api/info?loc=<slug>&k=<first|return>&m=<standalone|browser>`. `loc` is the slug shown, or `none` on the picker page and the not found view. `k` is `first` when no `rowhether-last-v1` existed when the start began (`main.js` reads `loadLast()` before anything writes it, and the old-key move counts as an earlier visit), else `return`. `m` is `standalone` from the home screen. The Worker writes one Analytics Engine point when `OPENS` exists and all three words are valid: the slug as the index, the instance, `k` and `m` as blobs, and 1. It reads no IP address, user agent, country or account, and writes nothing for a missing or bad word. `OPENS` is `rowhether_opens` (`rowhether_opens_dev` on Previews), read back through `ANALYTICS_SQL`, and points are kept three months. Nothing else goes into the request or the point without the owner's go-ahead. `/privacy` (`privacy.html`) says what is counted and what the browser keeps, and the install steps note and the Settings intro note link to it as "How RoWhether counts app opens." The footer does not link it.
- Must build to plain static files in `dist/` that any static host can serve. Cloudflare Workers static assets is the target.
- `localStorage` holds settings and a cache of the last good data. Keys are `rowhether-<name>-v<n>`, with `:<slug>` on the ones that belong to one location (`KEYS` in `src/config.js`). The first load copies the old `putney-rowing-*` keys across once and leaves them in place (`migrateStorage()`). Every access is wrapped in try/catch.
- All times display in the location's zone (`loc.tz`, `America/New_York` for Putney) regardless of the viewer's time zone. Open-Meteo is requested with `timeformat=unixtime` to avoid parsing local strings. Today and Tomorrow count local dates (`addDays()` on the day key), never 24 hours, since a local day can be 23 or 25 hours long.

## Location and endpoints

- Putney Landing is data, not code: `data/locations/putney-landing.json` (the place, its limits, the course heading, its words) and `data/waterways/connecticut-river-vernon-pool.json` (the river's gauges, station and alerts). The build writes them to `locations/putney-landing.json` with the waterway inlined. The app reads that file, or the copy saved in the browser, and resolves it into the `loc` that `fetchAll(loc)`, `buildModel(loc, ...)` and the render code read.
- Dock: 42.9607, -72.5219. The point resolves to NWS office GYX (Gray), grid 3,13, forecast zone NHZ011 and county NHC005 (Cheshire, NH). Alerts are asked for by four zones, one forecast zone and county on each bank: VTZ015 and VTC025 (Windham, VT) from the Albany office and NHZ011 and NHC005 from Gray.
- The URLs below are what Putney asks for. `bindingsFor(loc)` in `src/sources/index.js` builds them from the location's source rows, one adapter per provider, and the golden and browser tests pin them.
- Open-Meteo forecast: `current`, `hourly` (temperature, apparent temp, dew point, precip probability, precip, weather code, wind speed, gusts, direction, visibility, CAPE, cloud cover) and `daily` (sunrise, sunset, max/min temp, max precip probability). Units mph, °F, inches. 7 days.
- NWS alerts: `https://api.weather.gov/alerts/active?zone=VTZ015,VTC025,NHZ011,NHC005`. A location's alerts row is `zones:<code>,<code>` or `point:<lat>,<lon>` (`point` asks at that point).
- NWS observation: `https://api.weather.gov/stations/KEEN/observations/latest` (km/h and °C, converted)
- USGS latest values (newer OGC API, not legacy waterservices): `https://api.waterdata.usgs.gov/ogcapi/v1/collections/latest-continuous/items?monitoring_location_id=USGS-01154500,USGS-01161280&parameter_code=00060,00010&f=json&limit=50`. Each gauge is listed once, and `limit` is there because the service answers 10 readings at most without it; a gauge can list several series for one parameter, and the newest reading is kept
- USGS 48 h flow series: `https://api.waterdata.usgs.gov/ogcapi/v1/collections/continuous/items?monitoring_location_id=USGS-01154500&parameter_code=00060&time=P2D&limit=1000&properties=time,value&f=json`
- Air quality (Open-Meteo, CAMS): `https://air-quality-api.open-meteo.com/v1/air-quality?latitude=42.9607&longitude=-72.5219&hourly=us_aqi,pm2_5&timezone=America/New_York&timeformat=unixtime&forecast_days=5`
- Model comparison (Open-Meteo): the same forecast endpoint with `hourly=wind_speed_10m,precipitation` and `models=gfs_seamless,ecmwf_ifs025,gem_seamless,icon_seamless` (`MODELS` in `src/config.js`). Fields come back suffixed with the model id. GEM has no separate gusts, so only sustained wind is compared.
- The main forecast also asks for hourly `uv_index` and daily `uv_index_max`, for the Light tab.
- USGS 30 day daily mean flow: `https://api.waterdata.usgs.gov/ogcapi/v1/collections/daily/items?monitoring_location_id=USGS-01154500&parameter_code=00060&statistic_id=00003&time=P30D&limit=100&properties=time,value&f=json`. The latest day lags by a day or two. Each day sits at noon in the gauge's zone (the flow row's `tz`, else the location's), so a winter date is 17:00 UTC at Putney.
- NWS river forecast for the same gauge (NWPS id WLPN3, NERFC), 3 days in 6-hour steps, flow in kcfs: `https://api.water.noaa.gov/nwps/v1/gauges/WLPN3/stageflow/forecast`. Information only; the call uses the latest measured flow.
- NWS tide forecast, for a location with a `tide` row (Thompson Boat Center, point GTND2): the same service and the same path, `https://api.water.noaa.gov/nwps/v1/gauges/GTND2/stageflow/forecast`. 72 hourly heights in feet in `primary`, with `primaryName` "Tide Height" and `secondary` -999. `parseTide()` refuses an answer whose primary series is not a tide height, drops -999 and null, and takes the highs and lows as the local maxima and minima of the hourly series (the middle of a run of equal hours, since heights come to a tenth). Information only: no reason in `assess()`.
- Refresh every 10 minutes while visible, and on return to the tab if data is over 5 minutes old. Each source fails independently; the last good value is kept and the failure is named under the hero. With no saved forecast and no connection, the hero says "No forecast saved for this location on this phone yet. Connect to load it." in place of the blocked sources text. A saved forecast is drawn whole at start, whatever its age. A source whose last good fetch is older than its `staleMs` (alerts 1 hour, observations 3 hours, the forecast, air quality, models, gauge readings and the river forecast 24 hours, daily means 7 days) reads as missing, but only once a refresh in this visit has failed for it: a forecast past its limit then reads "No data.", and alerts that are past it are named in the hero ("Official alerts not checked: no answer from NWS for 2 hours."). Two sources are never dropped this way: alerts still in force by their own end time stay, and the gauge's readings (the latest reading and the 48 hour series) stand or fall by the reading's own time against `flow.maxAgeH` and `waterTemp.maxAgeH`, as Call logic says. The time of each source's last good fetch is saved with the forecast (`fetched`). The hero's `#notChecked` line also says what a location has no source for ("Not checked here: river flow, official alerts.") and a gauge that has not reported within `flow.maxAgeH`.
- Town search (the picker only, Open-Meteo geocoding, keyless, `access-control-allow-origin: *`): `https://geocoding-api.open-meteo.com/v1/search?name=<q>&count=5&language=en&format=json`. Asked after 300 ms with no typing or on Enter, at most once per 300 ms, and gives up after 8 seconds. It sends only what the viewer typed. The address under a missing page is put in the box but is sent only after the viewer types or presses Enter.

## Call logic

Levels: 0 go, 1 caution, 2 stay off. An hour's level is the worst of its reasons (`assess()`):

- Dark (sun below civil twilight) is 2. Twilight before sunrise or after sunset is 1 (lights required).
- Thunderstorm codes 95/96/99 are 2. CAPE >= 1000 with rain chance >= 30% is 1.
- Freezing rain is 2. Snow is 1. Precip >= 0.15 in/hr is 1.
- Rain chance against the settings thresholds (`rainCaution`, `rainOff`, defaults 60% and 90%). Either can be blank, which turns that level off.
- Wind and gusts against the settings thresholds.
- Visibility < 0.25 mi is 2, < 1 mi is 1. Otherwise likely fog from `fogRisk()` is 1. Possible fog is shown but does not change the call.
- Air below 32°F is 2. Air plus water below the cold line is 1.
- Flow against the settings thresholds, counted only while the latest reading is within the location's `flow.maxAgeH` (24 hours at Putney). An older reading is shown with its age and not used for Go, Caution or Stay off, wind against the current or the debris warning. The gauge's water temperature counts for the cold check only within `waterTemp.maxAgeH` (72 hours at Putney). A flow limit is for one gauge: the location's carries `thresholds.basis.flow` (`adapter:ref:unit`, `usgs-ogc:USGS-01154500:cfs` at Putney) and the viewer's carries `limitBasis.flow`, and each applies only while it names the location's primary flow binding. A viewer's limit saved with no gauge named is read as made for the current one. A limit for another gauge is not used and is kept, and Settings and the River view say "Your flow limits were for the <label> gauge. Set them again for this gauge."
- Active NWS alerts apply to hours they cover. Thunderstorm, flood, wind, dense fog and winter storm types are 2, others 1. A storm-based warning lists its whole county but is drawn as a polygon, so one with a polygon applies only when the polygon contains the dock point (`parseAlerts()`, with the dock point in the binding); a product with no polygon applies to every location in its zones. Eight whole event names are Stay off too (`STAY_OFF_EVENTS`, matched whole and in any case): Small Craft Advisory, Gale Warning, Storm Warning, Special Marine Warning, Hurricane Force Wind Warning, Hurricane Warning, Storm Surge Warning and Tropical Storm Warning.
- Air quality (US AQI) against the settings (`aqiCaution`, `aqiOff`, defaults 151 and 201). Either can be blank, which turns that level off.

Fog (`fogRisk()`, thresholds in `FOG` in `src/config.js`) is none, possible or likely, with a type:

- Valley fog, midnight through the 10 AM hour. Likely: air within 2°F of the dew point, wind <= 4 mph, mean cloud cover over the last 6 hours <= 50%. Possible: within 4°F, wind <= 6, cloud <= 80%. Missing cloud cover counts as clear.
- Steam fog, same hours. Likely: water at least 18°F warmer than the air, wind <= 6, humidity >= 75%. Possible: 10°F, wind <= 8, humidity >= 60%. Uses the gauge or the Settings water reading.
- Model fog at any hour: weather code 45 or 48, or visibility under 1 mi.

`morningFog()` takes the strongest risk from an hour before first light through the 10 AM hour, and says fog lifts at the end of the last foggy hour. If that is the 10 AM hour it says the fog lingers into late morning. Fog appears in the Visibility fact (now, or the next morning), and each Day by day row and its full forecast.

Hourly level is evaluated at mid-hour for daylight.

Night is not shown. The rowing day is first light to sunset, split into periods (`PERIODS` in `src/config.js`, built by `periodsFor()`): morning from first light to 10 AM, midday 10 AM to 3 PM, afternoon 3 PM to sunset. A period's call is its worst remaining hour, ignoring light (`lvlExcept(a, LIGHT_KEYS)`); the need for lights before sunrise is a note (`lightsUntil`). Finished periods are hidden. `m.daytime` is true from first light to sunset. Outside it, the hero shows `m.next`, the next period, and On the water now is hidden. In daytime, "holds" looks only as far as sunset. When the call is not go, the hero names the next go period.

Water state (`waterState()`, thresholds in `WATER` in `src/config.js`) is information only and does not change the call:

- Chop wind for an hour (`chopWind()`) is the along-course wind component plus 0.4 times the crosswind component. Wind blowing upstream (from downstream) against the current is multiplied by 1.25 over 10,000 cfs and 1.4 over 20,000 cfs.
- On still water (a lake, reservoir or harbor, `water.mode` `fetch`) there is no current. Chop wind is the wind times the square root of the fetch over 2,000 m, kept between 0.25 and 2 (`fetchFactor()`). The fetch is the chord of the lake's ellipse along the wind, one distance for every direction, or the nearest of 16 measured ones (`fetchAt()`), and the reference when the record has none.
- The hour's value blends this hour and the two before it (0.5, 0.3, 0.2), since chop builds and settles.
- Under 5 mph is flat, 5 to 9 light chop, 9 to 13 chop, 13 and up rough.
- `waterWhy()` names the wind as along the straight or crosswind using the same 60° split as `windVsCourse()`, so the two notes never disagree.
- On a tidal reach (`water.mode` `tidal`) there is no current data, so chop is the river formula with the crosswind weight and no multiplier, whatever the record's `flow.against` holds (`againstSteps()`): a river's step would point the wrong way on a flood. `waterWhy()` adds "Flood tide, rising until about 7 AM." or "Ebb tide, falling until about 1 PM." With heights only, rising water is flood and falling is ebb. The tide is on the hour's water state (`tideAt()`, `tideEvents()`, `tideLine()`).
- On a canal (`water.mode` `canal`) the chop is the same: the river formula with the crosswind weight and no multiplier, even with a flow binding and a `flow.against` in the record. Flow reasons and the debris warning still apply. `waterWhy()` says the width of "the canal" where a river says "the river".
- A harbor is `fetch` mode, as above, with the tide on its water state and the Tide tab only where it has a `tide` row. The Wind tab says "Swell from open water is not included." No curated location is a canal or a harbor yet.
- On still water `waterWhy()` says how much open water the wind has instead ("Wind from the SW has about 1.5 mi of open water to build waves.", or "crosses only about 0.4 mi of water, so chop stays small" under 1,000 m).
- A flow rise of 20% or more in 6 hours adds a floating debris warning (`debrisLikely()`), shown now and for today's periods.
- Shown in the hero, On the water now, a second chip on each Day by day row (worst hour), the full forecast (range and peak time), and a Water column in the hour table.

Precipitation is information on top of the rain chance rules above:

- `precipKind()` names what is falling from the weather code (drizzle, rain, showers, snow, freezing rain, thunderstorms). `rateWord()` calls an hourly amount light, moderate or heavy (0.1 and 0.3 in/hr).
- `precipSummary(hours)` gives the peak chance and its hour, the run of hours within 10 points of the peak ("most likely 1 to 3 PM"), the total amount, and the most common kind among hours with at least 30% or a measurable amount.
- The Precipitation section (`precipBlock()` in `src/render/precip.js`) appears in two places. On the water now covers from the current hour to 6 hours ahead or sunset, whichever is first, led by what is falling now. Each full forecast covers its period. The section has a headline chance (colored by the worst precipitation reason in the window), timing, kind and amount, and an hourly column chart (`precipChart()` in `src/render/parts.js`). Columns over the rain caution or stay-off setting take that status color, and the settings are drawn as labeled dashed lines. Only the peak is labeled. Tapping, hovering or focusing a column shows that hour under the chart. The hour table keeps the Rain column as the full set of values.

Wind vs course uses `relWind()`: the angle between where the wind comes from and the upstream heading. Within 60° either way is head or tail; otherwise crosswind, with the side named as the NH (east) or VT (west) bank. A location whose record has no `banks` and a heading course gets them from the heading (`autoBanks()`): facing upstream, the right side faces the heading plus 90°, named by its 8-point compass name, so a 330° course has a northeast and a southwest bank. Still water says shore. A `none` course (a lake with no course set) gives no head or crosswind sentence, and the Wind tab draws no arrows and no Course column. On still water the head and crosswind sentences leave out the chop line, which the water state covers.

## Tabs and detail views

The home screen is the quick answer. Within a location, the tab bar under the header is the only navigation: Now (the home screen), Week, Wind, River, Storms, Fog, Temperature, Rain, Light, Air: the summaries, then most to least important (`VIEWS` in `src/render/detail/index.js`). A tidal location also has Tide, after Wind, from its `tide` row. Tabs are text with an underline, pinned to the top on scroll, so they read as places and the pill buttons stay actions. Tapping a fact in On the water now or in a full forecast opens the matching tab (for that day, from a forecast). The location name in the header opens the switcher (the picker); the account button will open Account (phase 2). Pages outside a location use the same text tabs. Views are in `src/render/detail/`.

- Routes (`src/route.js`): a location is at `/<slug>`, such as `/putney-landing`, and the tab is in the hash. No hash or `#now` is home; `#wind`, or `#wind/2026-10-14` for one day. `/` opens the last location the viewer opened. With none stored it is Putney Landing with the note "Not your water? Pick a location." and the address left as `/`, until `FIRST_VISIT_PUTNEY_UNTIL` in `src/config.js` (a placeholder, 1 March 2027: the owner sets it with the merge to master), then the picker page. Dismiss on the note stores Putney as the last location, and so does picking Putney. `?open=picker` opens the picker over the last location (the picker page when there is none) and is taken out of the address. An entry for `/` remembers what it showed (`history.state.home`), so Back returns to the picker page, or to Putney with its note, and not to the location chosen since. Any other address is the not found page, which ends in the picker search. A hash for a tab the location does not have is dropped. Switching back to Now restores the home scroll position. The tab names the view, so each view's heading is visually hidden and its opening line leads.
- Week: Plan a row first, then one row per day: a bar from first light to sunset on a clock axis shared by all days (the part already over is faded), and one line per concern in words, time first ("1 to 5 PM: gusts to 26 mph"). A day the models disagree on gets a low confidence line. A day opens to a bar for each factor that matters, linked to its tab, and one line naming the factors with no concern. Built from `callRuns()` and `factorRuns()`.
- Plan a row (`planSessions()`): pick a session length (1, 1.5 or 2 hours) and a time of day (any, morning done by noon, afternoon from noon). For each day it finds the go session with the least chop, gusts and rain chance, and lists up to five, calmest first, plus the longest go stretch. Choices are saved in `localStorage` (`PLAN_KEY`).
- Tide: the NWS tide forecast for a tidal location (`src/render/detail/tide.js`, a chunk of its own that loads the first time the tab opens). A week strip of the days with a high ("High 5.9 ft", no status color, "No tide forecast" after the 3 days), a chart of the rowing window with the height lane and each high and low labeled, the readout, an Hour by hour table (Time, Height, Tide) and How this works. Information only.
- Storms: NWS alerts as bars over the next 3 days with their full text, then thunderstorm risk and its ingredients (CAPE with the 1,000 J/kg line, rain chance with the 30% line, gusts).
- Air: US AQI and PM2.5 against the settings. The forecast covers 5 days; later days show no data.
- Light: first light, sunrise, sunset and dark for the picked day with the change from the day before, the UV index by hour, and a six-month chart of daylight and twilight. Times come from `sunOn()` (SunCalc), so they work for any date.
- The day-based views have a week strip (one button per day, a small bar and value, colored by that factor's worst level) that picks the day, then a chart of that day's rowing window (fog: midnight to 11 AM), a legend, a readout for the tapped hour, an "Hour by hour" table twin, and a "How this works" panel that states the rules with the current settings. A picked day carries across views. Sections the viewer opens (`details[data-keep]`) stay open through the 10-minute refresh.
- Forecast confidence (`confidence()`, thresholds in `CONFIDENCE`): the mean spread of sustained wind across the compared models, and the share of hours where some show rain and others do not. High, medium or low. Wind shows the model range as its own lane; Rain shows how many models show rain each hour. Information only; the call uses the main forecast.
- Charts use `Chart` in `src/render/chart.js`: one time axis, stacked lanes each with their own y scale (no dual axes), settings as dashed status lines, hit columns spanning all lanes. Charts are drawn at the measured page width so SVG text is real size, and redrawn on resize.
- Color: river teal for the main series, muted gray for a secondary one, status colors only where they mean go, caution or stay off. Go and stay off are close for red-green color blindness, so stay off carries a fine diagonal hatch in the Week bars and legend.

## Now screen additions

- The header: the location's name is a button with a small chevron after it (it opens the picker), the line under it names the zone and, on a device in another zone, how far it is from the viewer ("All times Eastern, 1 hour ahead of you."), and a published location carries the badge "Not confirmed on site". The footer credits are the location's `copy.credits`, with `[text](https://...)` links (`linkText()`). The time reads "Updated 6:41 AM", or "Saved 6:41 AM" for a saved copy, with the day when it is older ("Saved Mon 6:41 AM" for the six days before, then "Saved Oct 14, 6:41 AM"). The install bar, the install dialog and the manifest say RoWhether.
- Share this forecast: a quiet button under the hero. It sends the hero as text (verdict, reason, conditions, how long it holds) with the location's page (`SITE_URL` plus its slug on production, such as `https://rowhether.com/putney-landing`, and the page's own address on dev) through the phone's share sheet, or copies it where there is none (`src/share.js`). The text starts "Putney Landing rowing, 6:41 AM:" and adds the location's zone name after the time ("6:41 AM Eastern:") only when the device's zone has another offset from it at that moment.
- Dock reports (`src/reports.js`, `worker/reports.js`): at the top of On the water now, the latest report from the last 3 hours ("At the dock: flat water, patchy fog, 20 min ago"), compared with the forecast water state for that hour, and a Report conditions button. The dialog has choices only: water (flat, light chop, chop, rough), fog (none, patchy, thick) and floating debris. No free text, so nothing to moderate. Rate limited to 3 a minute per connection. Hidden when `/api/info` says reports are off, and on a static host with no `/api`.
- Air quality fact, linking to the Air tab. Daylight links to Light. A tidal location has a Tide fact after the water state, linking to the Tide tab: the height now and whether it is rising or falling, then "High about 7 AM, 5.2 ft. Low about 1 PM, 2.4 ft.".
- The picker (`src/picker.js`, a lazy chunk with its own `picker.css`, precached, read on the first tap of the location name, for `?open=picker`, the picker page or the not found view): a `<dialog id="picker">` sheet over the location, with the current location first ("Showing now"), the search ("Find a location"), Recent (up to 8, without the current one), All locations by region, and "Suggest a location" when the suggestion form is configured. The page at `/` and the search under a missing address are drawn in `#notFound` with the same search and lists. Search runs on the precached `locations/index.json` from 2 characters, at most 8 rows, with no request for the list while typing: a name that starts with the query, then a name with a word that does, then a short name, locality or waterway with a word that does (`matchRank()`), ties by recent, then by name; accents and case do not matter (`fold()`). A row is `<a href="/<slug>" data-nav>` with the name and "<locality>. <waterway>."; choosing one opens the location, moves focus to the title and says "Showing <name>." in `#pageAnnounce`. Near me, a button under the search, asks the browser for the position only on a tap (not at all when the permission is already denied), at low accuracy, rounds it to 2 decimals before anything uses it and keeps it nowhere. It lists the locations within 100 km nearest first under "Near you" with the distance in miles (`whereAmI()`, `nearest()`, `miles()`). The town search (`fetchPlaces()`) shows up to 5 places under "Places" as "<name>, <admin1>, <country>"; choosing one lists the locations within 50 km of it, or says there are none. While it runs, a search with no match says it is looking for towns, and a failed or offline search says "Town search is not available right now. Location names still work." ## Design system

- Colors are CSS custom properties on `:root`, redefined for `prefers-color-scheme: dark` and `[data-theme]`. Light base is a cool fog white (#EEF3F2) with deep river teal (#1E4A52). Dark base is deep river (#0F2329), not near-black. Status: go spruce green, caution maple amber, stay off signal red, each with a soft tint.
- Type is Archivo variable (CSS family name `"Archivo Variable"`), one family. Width does the work: the verdict word is width 125%, weight 850. Numbers are width ~78% with tabular figures.
- The hero verdict is the one loud element. Everything else stays quiet.
- Sections are separated by surface panels on the page background: On the water now is one panel, each day in Day by day is its own panel, and period rows inside sit on the page background with a status-colored left bar.
- Avoid: all-caps labels, eyebrow labels, middle-dot separators, monospace data labels, identical rounded card grids, decorative gradients.
- Responsive to 360 px. Visible keyboard focus. Day by day rows are native `<details>`, so they work with the keyboard. Respect reduced motion.
